# Публикация демобазы 1С на Windows

Этот путь нужен для проверки настоящего HTTP-сервиса. Текущий Docker Compose
по умолчанию продолжает использовать `source-mock`; успешный mock-прогон не
подтверждает интеграцию с 1С.

## Подготовка

1. Установите официальную платформу 1С для Windows с компонентом **«Модули
   расширения веб-сервера»**. Нужна действующая лицензия разработки. Для
   восстановления выгрузки желательно использовать версию 8.3.27.1606,
   которой она была создана; если версия другая, сначала проверьте
   совместимость на отдельной базе.
2. Включите IIS и компоненты разработки приложений, включая поддержку ISAPI.
   Используйте локальную публикацию; для доступа из интернета требуется HTTPS
   и отдельная настройка защиты.
3. Клонируйте репозиторий. Файл `onec/local/SverkaDemo.dt` исключён из Git:
   перенесите его с Mac отдельно в эту папку. Не добавляйте `.dt` или пароли
   в коммит.

## Восстановление и публикация

1. Создайте **новую пустую** файловую информационную базу 1С. Откройте её в
   Конфигураторе и выберите **Администрирование → Загрузить информационную базу**;
   укажите `SverkaDemo.dt`. Загрузка полностью заменяет содержимое выбранной
   базы, поэтому не выбирайте существующую рабочую базу.
2. Проверьте наличие справочников `ЛицевыеСчета`, `Начисления`, `Платежи`,
   HTTP-сервиса `ReconciliationAPI` и роли `APIReadOnly`. Убедитесь, что в базе
   есть отдельный пользователь с этой ролью. Сопоставление полей описано в
   [README.md](README.md).
3. Запустите Конфигуратор от имени администратора. Откройте
   **Администрирование → Публикация на веб-сервере**. Выберите IIS, имя
   публикации `SverkaDemo`, включите публикацию HTTP-сервисов и убедитесь,
   что `ReconciliationAPI` разрешён. Нажмите **Опубликовать**.
4. Проверьте в браузере Windows адрес
   `http://localhost/SverkaDemo/hs/api/accounts`. `api` — корневой URL
   сервиса в конфигурации, `accounts` — шаблон GET. Аналогично доступны
   `/charges` и `/payments`. Запрос с пользователем только для чтения должен
   вернуть JSON с массивом `value`, а запрос записи должен быть запрещён.

Если после публикации получен 404, сначала проверьте имя публикации, включение
HTTP-сервиса и сопоставление IIS с установленным модулем 1С. Если получен 401,
проверьте пользователя 1С и его роль. Наличие страницы веб-клиента само по себе
не подтверждает работу HTTP-сервиса.

## Подключение приложения

В локальном `.env` на Windows укажите адрес, доступный **из контейнера API**:

```dotenv
ONEC_BASE_URL=http://host.docker.internal/SverkaDemo/hs/api
ONEC_USER=<имя пользователя только для чтения>
ONEC_PASSWORD=<пароль>
```

После этого пересоздайте API и проверьте именно реальный источник:

```powershell
docker compose up -d --build --wait
docker compose exec api uv run --frozen --no-dev python scripts/preflight.py --real
```

Ожидается JSON со статусом `PASS` и `mode: real`. Только после такого результата
запускайте импорт и сверку и сравнивайте отчёт с данными опубликованной базы.
Если preflight выдаёт `BLOCKED`, запишите точную причину; не переходите на mock
и не называйте его результат проверкой настоящей 1С.
