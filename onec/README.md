# Подготовка 1С

Статус: исходники минимальной конфигурации сохранены в `onec/configuration`.
В пользовательском сеансе показаны записи справочников и настроенный HTTP-сервис;
экспорт этого состояния базы и автоматическая загрузка фикстур в репозитории
отсутствуют. HTTP-публикация и проверка запросов к настоящей 1С пока `BLOCKED`.

На 01.10.2026 использовалась учебная платформа 8.3.27.1606 для macOS:
`/Applications/1cv8t.localized/8.3.27.1606/1cv8t.app` (x86_64).
Компоненты webinst/wsap в этой установке не найдены. Это не доказательство
невозможности публикации в других установках 1С.

## Сохранённая конфигурация и mapping

Используем три справочника: ТЗ требует сущности, но не требует документы и проведение.

| Контракт | Объект 1С | Реквизиты |
|---|---|---|
| accounts | ЛицевыеСчета | ВнешнийID: строка 64; НомерСчета: строка 32 |
| charges | Начисления | ВнешнийID: строка 64; ЛицевойСчет: ссылка ЛицевыеСчета; Период: строка 7; СуммаКопеек: число 15,0 |
| payments | Платежи | ВнешнийID: строка 64; ЛицевойСчет: ссылка ЛицевыеСчета; ДатаПлатежа: дата; СуммаКопеек: число 15,0 |

ВнешнийID сохраняет ID из ../fixtures/data.json. В HTTP-ответе account_id берётся
из ВнешнийID связанного лицевого счёта, не из внутреннего UUID.
Период передаётся YYYY-MM, дата YYYY-MM-DD, суммы — целые копейки.
В исходниках HTTP-сервис `ReconciliationAPI` объявляет GET-шаблоны `accounts`,
`charges`, `payments`. Его модуль формирует JSON с обёрткой `{ "value": [...] }`
по [контракту](../CONTRACT.md). Наличие обработчиков в конфигурации не подтверждает,
что опубликованный endpoint работает или что роль `APIReadOnly` проверена
запросами. OData разрешён заданием, но здесь выбран собственный HTTP JSON.

## Что ещё нужно для интеграционного прогона

1. В подходящей установке 1С загрузить исходники конфигурации и воспроизводимо
   загрузить записи из `fixtures/data.json` по `ВнешнийID`. Скрипт такой загрузки
   пока не добавлен; ручной ввод нельзя считать доказательством повторяемости.
2. Опубликовать `ReconciliationAPI`, создать пользователя с ролью `APIReadOnly`
   и проверить GET трёх коллекций, а также отказ на запись.
3. Указать реальный `ONEC_BASE_URL`, `ONEC_USER`, `ONEC_PASSWORD` в локальном `.env`.
   Выполнить `uv run --env-file .env python scripts/preflight.py --real` и затем
   импорт, повторный импорт и сверку с опубликованным источником.
4. Добавить и проверить команду восстановления демобазы 1С. Сейчас скрипт
   `scripts/discrepancy.py restore` восстанавливает только тестовую PostgreSQL.
   Для демонстрации расхождений исходную 1С изменять не нужно.

Пока нет работающего endpoint, интеграционный прогон считается не выполненным.
Наличие Конфигуратора и разработанная конфигурация сами по себе его не подтверждают.

## Доступ к платформе

Сейчас у пользователя только учебная версия. Для варианта публикации на Linux/VM
потребуется подходящий официальный дистрибутив и доступная лицензия разработки.
Комьюнити-лицензия и учебная платформа — разные варианты:
https://v8.1c.ru/podderzhka-i-obuchenie/uchebnye-versii/
Доступ начинается с https://developer.1c.ru/ .
Установщики, лицензии и секреты в Git не помещаем. ТЗ отводит на 1С до 4 часов;
ожидание внешнего доступа учитывается отдельно. Команды установки и восстановления
будут записаны после проверки выбранного окружения, а не выданы за выполненные заранее.
