# Подготовка настоящей 1С

**PASS:** настоящая 1С 8.3.27.1508 опубликована через Apache в Linux/Docker на Mac.
Проверены создание новой базы, две загрузки фикстур, роль APIReadOnly, три GET,
отказ POST/PUT/DELETE, импорт в PostgreSQL и MATCH → MISMATCH → MATCH.
[Запуск](linux/README.md) · [Доказательства](../docs/evidence/real-1c-run.json).

Исходники трёх справочников, HTTP-сервиса и ролей сохранены в `configuration`.
Демобаза хранится в отдельном Docker volume.
В учебной версии нет паролей пользователей: публикация привязана к APIReader,
порт доступен только на localhost. Для публичного развёртывания нужна иная схема
аутентификации на подходящей платформе; текущая инструкция предназначена для демо.

## Mapping

| Контракт | Объект 1С | Реквизиты |
|---|---|---|
| accounts | ЛицевыеСчета | ВнешнийID: строка 64; НомерСчета: строка 32 |
| charges | Начисления | ВнешнийID: строка 64; ЛицевойСчет: ссылка; Период: строка 7; СуммаКопеек: число 15,0 |
| payments | Платежи | ВнешнийID: строка 64; ЛицевойСчет: ссылка; ДатаПлатежа: дата; СуммаКопеек: число 15,0 |

`ВнешнийID` сохраняет ID из `fixtures/data.json`; `account_id` берётся из
`ВнешнийID` связанного счёта. Период YYYY-MM, дата YYYY-MM-DD, суммы в копейках.
Сервис `ReconciliationAPI`, корневой URL `api`, публикует только GET `accounts`,
`charges`, `payments`, JSON `{ "value": [...] }`. Выбран собственный HTTP JSON,
не стандартный OData. Роль `APIReadOnly` имеет Read/View справочников и Use GET-методов;
права записи каталогов не выданы. Фактический отказ записи проверен в Linux: все три справочника вернули
«Нарушение прав доступа!». HTTP-методы записи возвращают 405.

## Восстановление из репозитория

Подготовлен `scripts/onec_demo.py`: создаёт **новую** файловую базу, загружает XML,
обновляет конфигурацию БД, дважды запускает загрузку `fixtures/data.json` и сравнивает
прочитанные из справочников строки с исходными фикстурами. Суммы проверяет Python.
Существующий каталог базы или отчётов скрипт отказывается использовать.

Загрузка выполняется обычными правами пользователя в общей транзакции по ВнешнийID,
без привилегированного режима. В исходном HTTP-сервисе нет маршрута загрузки.
Служебный параметр запуска `demo-seed|<fixtures>|<report>` обрабатывается модулем
приложения и `CommonModules/DemoFixtures`. Он предназначен только для локальной
демобазы и не заменяет read-only HTTP-интеграцию.

Команда для окружения, где бинарник платформы действительно запускается:

```bash
uv sync --frozen
uv run python -m scripts.onec_demo \
  --platform /path/to/1cv8 \
  --database onec/local/restored-demo
```

Windows PowerShell:

```powershell
uv run python -m scripts.onec_demo --platform 'C:\Program Files\1cv8\8.3.27.1606\bin\1cv8.exe' --database onec/local/restored-demo
```

Чтобы воспроизвести восстановление повторно, задайте **другое новое имя каталога**.
Не удаляйте существующую рабочую базу ради проверки. Логи сохраняются рядом в
`<имя-базы>-logs`. `PASS` допустим только после двух завершённых загрузок и сравнения
всех записей. Даже этот PASS относится к локальной 1С, а не HTTP-публикации.

**Статус загрузчика: PASS на macOS 8.3.27.1606 и Linux 8.3.27.1508.**
Новая база создана, конфигурация обновлена; две загрузки дали точное совпадение
всех записей с fixtures. Дополнительно в Linux проверена настоящая HTTP-публикация.

## Настройка учебного доступа

`DemoFixtures.ПодготовитьДоступ` вызывается локально параметром `demo-access|<report>`
и только в новой базе без пользователей. Создаются DemoAdmin (FullAccess) и APIReader
(APIReadOnly). Повторный вызов отказывается менять существующих пользователей.
Параметр `demo-readonly|<report>` проверяет чтение и попытку записи под APIReader:
транзакция всегда откатывается. Эти команды не опубликованы через HTTP и не используют
привилегированный режим. Автоматизация: `linux/initialize.sh`.

Для запуска используйте [инструкцию Linux/Docker](linux/README.md).
