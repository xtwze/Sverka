# Расширение валидации

Контракт разбирается в `source/dto/source_dto.py`. После построения снимка
`validate_snapshot` вызывает каждую функцию из `DEFAULT_SOURCE_RULES`.
Все проверки выполняются до `Database.initialize()` и транзакции импорта.

Добавленное при доработке правило `unique_account_numbers` отклоняет два разных
ID с одинаковым `account_number`. Оно отражает существующий UNIQUE в PostgreSQL:
раньше такой источник доходил до ошибки БД, теперь получает ошибку контракта.
Новый бизнес-запрет на отрицательные суммы или произвольный формат ID не вводится.

Для нового правила достаточно функции с аргументом `SourceSnapshot` и добавления
её в `DEFAULT_SOURCE_RULES`. Для отдельного сценария можно передать
`parse_snapshot(payload, rules=(*DEFAULT_SOURCE_RULES, extra_rule))`.
Сам цикл валидации и `ImportService` остаются прежними.

Проверки:

```bash
uv run pytest -q tests/test_models.py -k 'new_rule or rules_can_be_extended'
```

Первый тест доказывает отказ на дубликате номера. Второй подключает независимую
функцию без изменения парсера и проверяет, что её ошибка доходит до вызывающего кода.
