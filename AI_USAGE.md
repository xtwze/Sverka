# Использование CLI-агента и навыков

Для работы с данными подготовлены три разрешённые CLI-команды:
`read_onec_charges`, `read_postgres_charges`, `reconcile_charges`. Они принимают
только период `YYYY-MM` и выводят JSON. Для PostgreSQL используется отдельная
роль `agent_reader` с правами чтения. Команду импорта агенту не предоставляем.

Для объяснения результатов подключена модель `qwen/qwen3.5-flash-02-23` через
RouterAI. Ключ хранится только в локальном `.env`. Пользователь вручную проверил
запуск приложения и работу чата с локальным mock-источником; текст конкретного
ответа модели здесь не зафиксирован и не используется как доказательство сумм.
Числа и расхождения в примерах ниже получены командами инструментов.

## Пример 1: валидация источника

Применён [навык валидации](skills/validate-source-data/SKILL.md) с `period=2026-08`
и `mode=mock`:

```bash
uv run --env-file .env python scripts/preflight.py
uv run --env-file .env python -m source.cli.agent_tools read_onec_charges --period 2026-08
```

Проверено: `PASS`, 2 счёта, 4 начисления, 1 платёж. Для августа прочитаны
`charge-1`, `charge-2`, `charge-3`: 3 начисления на `1140000` копеек.

## Пример 2: проверка отчёта

Применён [навык сверки](skills/verify-reconciliation-report/SKILL.md) с
`period=2026-08`:

```bash
uv run --env-file .env python -m source.cli.agent_tools read_onec_charges --period 2026-08
uv run --env-file .env python -m source.cli.agent_tools read_postgres_charges --period 2026-08
uv run --env-file .env python -m source.cli.agent_tools reconcile_charges --period 2026-08
```

Сначала оба чтения дали одинаковые ID и `1140000` копеек, отчёт — `MATCH`.
Тестовый скрипт изменил в PostgreSQL сумму `charge-2` с `24950` на `25050` копеек
и удалил `charge-3`. После этого отчёт вернул `MISMATCH` с двумя строками:
`amount_mismatch` для `charge-2` (`24950`/`25050`) и `missing_in_postgres` для
`charge-3` (`990000`/`null`). Итог PostgreSQL стал 2 начисления и `150100`
копеек против 3 и `1140000` у источника. Скрипт восстановил обе записи из
фикстур; повторная сверка вернула `MATCH` и ноль расхождений.

## Как подключена модель

Read-only операции объявлены через `@tool` из `langchain-core` и зарегистрированы
в явном списке `AgentTools`. В CLI модель может запросить только
`reconcile_charges`; приложение проверяет имя инструмента и период до вызова.
Веб-чат принимает выбранный период, сам вызывает `reconcile_charges` и
`summarize_payments`, а модели передаёт готовые результаты для объяснения.
Импорт и произвольный SQL этим инструментам недоступны. Команды чтения и сверки
проверяются независимо от модели.

## Ограничения

Все числовые результаты выше получены с локальным HTTP mock. Публикация настоящей
1С и работа против неё не проверены. Ручная проверка веб-чата не заменяет
проверку точности каждого ответа модели по исходному отчёту.
