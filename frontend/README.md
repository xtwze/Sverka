# Frontend-прототип сверки

React + TypeScript + Vite. Одна страница по fullstack.pdf v2.2.

## Запуск

Node.js 22.12+ (проверено на 26.3).

```sh
cd frontend
npm ci
npm run dev -- --port 5173
```

```sh
npm test
npm run build
```

## Что работает

Выбор месяца, демонстрация импорта и сверки, ожидание, ошибки, отчёт с ID запуска,
точными итогами и таблицей различий. Адаптивная страница, клавиатурный доступ,
reduced motion. Шрифт Onest поставляется локально через npm.

Это только frontend: реальные 1С, PostgreSQL, backend и CLI-agent не подключены.
Успех в демо не подтверждает реальную интеграцию. Панель сценариев предназначена
только для просмотра состояний прототипа и будет убрана при подключении backend.

## Ручная smoke-проверка

1. Оставить август 2026 и сценарий «Два расхождения», нажать «Запустить сверку».
2. Во время запроса кнопки и месяц недоступны, виден процесс выполнения.
3. Получить `charge-1` (нет записи) и `charge-2` (24950 → 25050 копеек).
   Итоги: 1С — 3 / 1140000; PostgreSQL — 2 / 1015050 копеек.
4. Нажать «Импортировать»: демонстрационные данные восстановлены,
   сценарий переключился на совпадение. Сверка даёт одинаковые итоги.
5. Повторить импорт: результат тот же. Это имитация UI, не тест UPSERT.
6. Выбрать «1С недоступна», запустить сверку: FAILED без ложных нулевых итогов.
   Импорт при том же сценарии также выдаёт ошибку.
7. Выбрать сентябрь 2026: одна запись, 5000 копеек. Другой месяц: явно пустые источники.
8. Сменить месяц/сценарий: старый отчёт сбрасывается. Очистить месяц: сверка заблокирована.
9. Проверить ширины 1440, 768 и 390 px, Tab-навигацию; таблица прокручивается внутри.

## Подключение backend позже

`src/types.ts` определяет интерфейс `ReconciliationGateway` и формат отчёта.
`src/demo.ts` возвращает фиксированные ответы на основе starter fixture;
не реализует самостоятельный движок reconciliation. Заменить `demoGateway`
на HTTP-адаптер, согласовать ошибки и API-контракт с Python.
Импорт и сверка — независимые операции. Сверка не исправляет записи.

## Объём

Нет авторизации, чата, очередей, дополнительных экранов, истории или экспорта.
Тесты проверяют демо-контракт, а не обязательные backend-интеграционные сценарии.
Starter kit перенесён в корень проекта. Перед первым коммитом нужно
сначала отдельно зафиксировать неизменённый starter kit, как требует задание;
затем добавить frontend следующим коммитом. Сейчас коммиты не создавались.

## Как объяснить код на ревью

- `src/main.tsx` — подключает React, шрифт и стили.
- `src/App.tsx` — хранит состояние страницы через `useState`, обрабатывает две кнопки,
  показывает загрузку или отчёт. `Loading` и `ReportView` — обычные функции-компоненты.
- `src/types.ts` — описывает поля отчёта и методы будущего API-адаптера.
- `src/demo.ts` — возвращает заранее подготовленные ответы и форматирует копейки.
  Задержка 850 мс позволяет увидеть загрузку. Никаких запросов к 1С здесь нет.
- `src/demo.test.ts` — проверяет суммы, периоды, ошибку источника и форматирование.
- `src/styles.css` — обычный CSS с медиазапросами для небольших экранов.

Последовательность: нажатие → `pending` → вызов адаптера → ответ/ошибка → снятие `pending`.
`AbortController` отменяет ожидание при размонтировании страницы. При изменении
периода старый отчёт очищается. Комментарии к этим решениям написаны на русском.
Нет Redux, роутера, отдельного UI-фреймворка или собственного сервера.
